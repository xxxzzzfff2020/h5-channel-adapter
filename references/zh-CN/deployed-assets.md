# CDN 子目录部署的图片与资源排查

适用于图片缺失、XML 错误、动态资源或部署前的路径兼容检查。复用当前工程和素材，不启动额外真机流程；真机自动化需另按[明确选择的流程](android-taptap-automation.md)确认。

2026-10-10 项目证据出现：本地根目录可加载的根相对图片，在 CDN 子目录部署后请求域名根部，返回 `404`／`application/xml`；包内正确地址返回 `200`／`image/webp`，字节与冻结资源一致。本地根与嵌套目录修复验证通过，但该修复包安卓复测仍待完成。这是路径问题的证据，不能写成 WebP 不受支持，也不证明所有破图都由同一原因造成。

## 先核对实际请求

固定待测构建、实际页面 URL／部署前缀及入口哈希，记录每个问题资源的最终 URL（含重定向）、HTTP 状态、MIME、响应字节／文件头和 SHA-256，与包内原件比较。`.webp` 扩展名不能证明返回的是图片；XML 错误页也可能被服务器错误标为 `200`。跨域读取受限时用允许的网络观察／原始 HTTP 读取，不为取证绕过权限或下载无关素材。

检查 `img.src`、`currentSrc`、`srcset`、SVG `image` 的 `href`／`xlink:href`、静态及运行时 CSS `url()`、CSS 变量／内联样式、预加载、图集和动画状态切换。不要只搜 HTML 或初始状态。CSS 中相对路径通常以样式表 URL 为基准，JS／SVG 生成的路径须核对实际解析基准；`document.baseURI` 可能受 `<base>` 影响，不能不加验证地统一套用。

例如页面位于 `https://cdn.example/game/build/index.html`，`/assets/hero.webp` 请求域名根部；`./assets/hero.webp` 才在当前页面目录下解析。按现有构建工具配置相对 `base` 或明确的部署前缀，集中修复实际运行时解析。保留官方 SDK 外链和确有意图的其他绝对 URL，不对所有字符串盲目替换，不将 SVG 内部 `#fragment` 当文件路径。

## 先解码，再核对画面

- 使用同一冻结产物分别在 `/` 和有代表性的嵌套目录加载；资源服务不能把错误请求回退成 HTML／假 `200`。覆盖出现问题的页面、人物状态、动画切换、320 等实际窄屏、返回及刷新，记录实际网络失败和页面错误。
- `img.complete` 为 true 也可能是失败；结合 `currentSrc`、`naturalWidth`／`naturalHeight` 和实际 [Image.decode()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode)。先检测方法是否可用，缺少接口不能误报格式解码失败；用现有加载事件、尺寸和画面取证，并保留 decode 待验。SVG／CSS 背景需记录实际 URL、加载／错误结果及对应图片解码，再检查相关截图或可见画面。HTTP 和 decode 通过仍不代表遮挡、裁剪或人物动画正确。
- 路径／响应错误先修路径；200 且字节匹配但解码失败才调查宿主格式／解码能力，解码成功却不可见再查渲染、尺寸、透明度及生命周期。不要盲目全转 PNG、重画素材或沿用本地根目录 PASS。
- 修复须保护素材原件、存档、经济和 SDK 行为，按影响运行必要检查。新包未经单独上传确认和对应安卓复测，结论保持本地修复通过／设备待验；桌面 WebP decode 不代替 Android WebView 解码证据。

资源哈希使用原始字节；CDP 中序列化 CSS／DOM 表示可能不同，单项入口一致不能写成所有资源一致。源码、包清单、网络、解码、画面和真机分别保留证据，真实地址／ID／令牌仅留项目记录。
