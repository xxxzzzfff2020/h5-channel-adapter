# H5 多平台适配

把已完成 TapTap 接入的 H5 项目转为各渠道可独立维护、可重建、配套物料齐全的交付。

平台入口包括 **233 乐园 H5、4399 H5 小游戏、小红书小工具、B 站 TOY、网易星匣**。按项目与平台实际能力适配；233 H5 不等于工坊／口袋方舟原生工程，4399 H5 小游戏不等于 H5 页游。

## 入口与范围

- 确认游戏根目录、TapTap 源目录、目标渠道以及首次适配、增量同步或平台规则更新。未指定目标则展示平台列表；选择“全部平台”时列明当前五个平台，并分别核对接入条件。
- 按目标读 [233](233.md)、[4399](4399.md)、[星匣](xingxia.md)、[小红书](xiaohongshu.md)、[B 站 TOY](bilibili-toy.md)。物料必读 [制作流程](materials.md)，非 TapTap 安卓渠道必读 [兼容与验收](compatibility.md)。
- 只处理本轮指定平台。已有上传／提审授权按原范围继续；无此授权则交付本地文件及后续信息，不自行操作用户日常浏览器、建平台应用或提交审核。

## 引导式对话入口

用户说“准备开始生成／开始多平台适配”而未选平台时，先按 [引导式交互](guided-flow.md) 用当前可用的对话提问工具给出平台选项，收到选择后再建立渠道目录。等待时可做来源与资源只读盘点。用户已指定平台或明确“全部已支持平台”则直接沿用，不重复问。讨论或演示流程本身不代表要求立即对当前游戏执行适配。

引导顺序是**选择平台与物料范围 → 本地初转与所选物料 → 按平台展示就绪/缺口 → 引导建项与填写必要字段 → 自动续做各平台出包**。无配置阻塞的平台先交可上传候选 ZIP，缺信息的平台停在相应步骤；一个平台等待 AppID 不阻塞其他平台。弹窗只问实际缺的信息，不为普通目录创建、转换或打包逐步请求批准。

## 第一轮：先做完本地可完成的交付

### 1. 固定来源并盘点资源

检查适用指令、版本、Git 分支及相关脏文件、活跃任务、已有渠道目录。无 Git 用文件哈希固定来源。正式名称取已确认产品资料，不从文件夹名猜测。

盘点**整个游戏根目录及 TapTap 工程内的资源位置**：母版、大图标、各比例宣传画、截图、宣传片、实际录屏、音乐、字体、文案、授权记录。先找已有文件，再向用户索取；不要求重传本地已有资料，不将备份或旧构建误认权威源。

可运行 `python3 <skill-dir>/scripts/inventory_project.py <游戏根目录> --output <本轮证据目录>/inventory.json`。工具默认只读盘点、哈希与图片文件头检查，不需要 FFmpeg；选择音视频检查才添加 --probe-av，不替代权威来源判断。按清单读取相关文本、查看候选图片；视频已选时才查看视频抽帧，不必逐张加载无关图片。

所有目标渠道使用同一份冻结 TapTap 来源，分别复制需要的源码、运行资源、锁文件、构建脚本与许可文件，不从另一个仍在变化的渠道串联复制。并发源发生变化时核对前后哈希并局部重新取样，不混用两个时间点。保留 TapTap、Maker 及其他渠道现场。

在删减渠道内容前，先按[包体超限流程](package-budget.md)检查冻结的原始包。超限平台先提示并选择方案；等待时继续其他渠道和独立物料，最终各渠道包仍须复测。

### 2. 实际建立独立工程

沿用已有结构。新项目默认：

```text
<游戏根目录>/
  Taptap项目/                 # 原源码保留原位
  233项目/                   # 渠道根本身就是完整源码工程
    src/、assets/、构建配置及锁文件
    上架物料/上传文件/        # 按平台字段分类及排序
    上架物料/制作记录/        # 母版、提示词、实录和剪辑记录
    docs/渠道交付.md
    docs/SOURCE_BASELINE.json
    docs/待补充信息.md
    evidence/                # 素材清单、验证证据与哈希
    dist-233/、release/       # 预览产物和版本化 ZIP
  4399项目/                  # 相同职责，独立源和配置
```

已有 `上架素材/` 等目录直接沿用，不为统一命名搬用户文件。运行资源必须实际复制或有可重现依赖，不软链接回写共享源。不仅建空目录或交复制命令。

复用原构建技术：Vite 用渠道 alias；原生 JS/Python 用构建装配适配层。不因参考工程使用 TypeScript 就换栈。集中处理 SDK、能力、广告、存档、容器与检查，不改玩法/奖励数值，不新增支付系统。

新渠道数据按游戏与渠道隔离；**已交付渠道保留原存档键、格式、版本、备份和奖励收据**。迁移有明确来源、备份、校验与用户选择，不自动导入其他渠道进度。

缺 AppID 仍完成适配层、素材、文案、兼容和可运行本地预览。身份配置明确为空，正式出包校验拒绝缺少的必需字段。不能借用其他游戏 ID，不能把 mock 发奖放进候选包；SDK 不可用仍可普通游玩。仅阻塞真正依赖缺失字段的功能。

### 3. 按范围制作上架物料

按 [物料流程](materials.md)、平台规格和本次物料范围生成文案、素材清单及预览；仅工程模式跳过物料流程。**游戏 ZIP 与物料 ZIP 分开**。不能只交图标、封面或包体就称整套完成。

只有选择视频处理时，233、4399 才制作“宣传片或品牌开场 + 真实玩法实录”合成视频。未选择视频时不录制、转码或调用 FFmpeg，按物料流程记录待补项。缺实录先在隔离浏览器实际录制；无法运行或确需实体设备证据才索取录像。缺构图可用当前可用的图像生成工具，遵守图像工具要求，保留母版/提示词；宣传插画不冒充实机截图。

某素材或规则缺失时继续其他交付，写清已搜索位置、具体缺口与影响，不伪造完成，也不把不依赖凭证的工作推迟到 AppID 阶段。

### 4. 检查并集中索取下一轮信息

执行相关构建、包检查与关键行为验证，查看最终图片和实际操作；选择视频时再查看视频拼接和播放。所有非 TapTap 安卓平台最低目标 **小米 8、Android 10**；无实体设备则明确待真机，不把目标说成通过。

每平台交付说明含输入版本/哈希、源码/输出路径、物料状态、检查范围、缺口和重建命令。按 [引导式交互](guided-flow.md) 展示逐平台状态表，区分“可上传候选 ZIP”“本地已准备、待建项/配置”“可出包、部分功能尚未开通”“素材/规则缺口”。**完成全部无信息依赖的工作后，自然询问第二轮信息**，通过选择题收集状态、文本题收集 ID；一次集中列出，仅索取确实需要且仍缺的字段。例如：

```text
第一轮本地准备已完成：<源码、物料、预览链接；若有缺口如实列出>。
请用建项资料在相应平台创建游戏，并补充：
- 4399：本游戏 AppID、广告/存档权限状态；使用排行时才需榜单 ID 和规则。
- 233：应用创建/绑定信息、广告能力或测试入口；现有 IAA 前端接口不需 AppID 参数。
- 其他平台：官方明确要求的公开 ID，或服务端凭证的安全配置位置。
收到必要信息后继续绑定、验证并出正式候选包，上传后再补测试地址。
```

区分 SecretID 与 SecretKey，先核对用途。服务端密钥放安全环境变量/凭证管理，获取配置位置即可，不写前端、ZIP、日志、公开文案或 Skill。不为 SDK 不需要的凭证卡住交付。信息已齐直接进第二轮，不重复问。

## 第二轮：绑定、出包与平台验证

核对游戏/渠道身份，填实际必需字段及已开通能力，重新构建验证，生成 `<游戏>_<渠道>_v<版本>_<日期>.zip` 和已选择制作的独立物料 ZIP，记录大小、SHA-256、入口哈希、文件列表和验证结果，保留旧包。正式包不得含占位配置、测试桥、演示存档、源环境文件、其他游戏 ID。

用户可分批补信息。将已收到的非敏感 ID、权限状态、未决问题更新到该平台已有交付/待补充记录，立即续做已具备条件的平台，不要求重新答整套问卷。权限待审核若不阻塞候选包，就使用安全降级并说明哪些功能未开通；不宣称广告/排行已可用。新增原游戏没有的排行榜须另有明确产品需求，不能只因后台提供权限就自动增加。

提供可点击源码目录、游戏 ZIP、物料 ZIP、建项文案、验证记录。用户自行上传则请求上传后的预览地址；已授权代上传则继续。预览 token 不进入长期知识库或公开报告。

分层报告本地、真实 SDK、真机、上传、审核、发布。真实广告和云档分别验完整观看奖励/取消及读写往返。选中文件、二维码出现、Build 通过均不是发布完成。

## 增量同步与新平台

TapTap 更新时用上次 SOURCE_BASELINE、当前渠道、当前 TapTap 三方比对，仅合并上游功能变化，保留渠道钩子、存档与兼容。视频工作已选时，UI 变化重录相关画面，旧录屏标旧版本；未变品牌素材复用重验，避免无意义重画。

新增平台或修正规则按 [扩展流程](extending.md) 更新 Skill。区分项目要求、官方规则与实现选择，保留来源和日期；单个游戏的数值、ID 和付费路线留在项目配置中。
