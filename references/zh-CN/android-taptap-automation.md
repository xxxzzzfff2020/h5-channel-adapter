# 按需启用的安卓真机 TapTap H5 自动化

仅在 Owner **明确要求安卓真机自动化适配或测试流程**时读取并执行。普通接平台、本地适配、Skill 维护或只读审计不启动此流程，不安装环境、不占设备、不上传。2026-10-10 项目证据验证了一条 USB 真机 → ADB／现有 Node → 官方 MCP 版本信息 → 二维码 → TapTap H5 → 有条件的 CDP → 游戏 UI 打开只读榜单路线；它不是所有手机、发行 WebView、模拟器或 SDK 用例的通过证明。

## 启动前说明并确认

先根据已有项目记录和本机工具清单准备完整说明，再使用**实际可用于确认的用户输入弹窗**，例如当前可用且允许此类确认的 `request_user_input_async`。提供“继续已说明流程”和“取消”选项，并等待 Owner 明确回答；默认选中、超时、沉默、其他聊天消息均不是同意。工具限制不允许审批或没有弹窗能力时，明确说明，展示同一完整说明并等待文字确认；不能伪称已弹窗。维护本参考时不弹启动窗、不执行设备流程。

下面是需填完真实信息的弹窗内容模板，不是工具调用指令：

项目／目标 app_id：<已核实目标>；设备：<Owner 选定设备，未知则先说明只枚举不控制>。
当前包：<路径、版本、SHA-256／目录清单哈希>；计划优先复用现有上传，不重传。
步骤：检测现有 ADB／Node／官方 MCP → 核实 USB 授权和宿主 → 取得当前版本对应二维码 → ADB 传入二维码并控制扫码／重启 → 核对实际 URL、运行版本与入口哈希 → 执行下面列出的 SDK 用例 → 保存证据和释放本轮资源。

## 检测并复用现有能力

- USB 安卓真机优先。确认唯一设备、USB 调试授权、Android／TapTap／可见内核版本以及本轮设备控制负责人；多设备或共享控制冲突先解决，不能默认控制第一个设备。仅在启动确认后运行 ADB 设备命令。
- 检测实际可用 ADB、Node 和官方 MCP 工具及版本；没有 Mobile MCP 不等于无方案。不为此搭建全套环境、安装全局工具或改 Provider。确有缺失时说明所缺能力，停止依赖步骤；现有 Node 的 WebSocket 等能力也须实测。
- USB 路线失败后，模拟器仅为需另行说明并核实的后备。不能把模拟器可启动、ADB 可连接或 CDP 可见当作 TapTap H5、真机或 SDK 验收通过。
- ADB 控制包括传图／媒体索引、UI 操作、必要重启、截图和有界日志；不清空 App 数据、账号或玩家存档，不重置共享 ADB 服务。仅清理本轮创建的端口转发和临时文件，按控制权交还设备。

USB 授权和工具能力以 [ADB 官方文档](https://developer.android.com/tools/adb)为依据，执行时核对当前工具支持；本参考不授予连接、控制或安装权限。

## 复用包、刷新身份和生成入口

1. 优先使用已有上传包、真实应用绑定和已获准用例。新包上传遵循 [TapTap 自动提审边界](taptap.md#自动提审与发布影响)及[逐制品确认](h5-reliability.md#h5-外部上传确认)。不要为拿测试入口或刷新版本重传；启动流程同意不替代这些确认。
2. 区分 `app_id`、`miniapp_id`、预览 `version_id` 和后台包体 ID。按当前 schema 强制刷新官方应用信息，例如已发现工具支持 `get_current_app_info(ignore_cache=true)`；用实际返回、已暴露的 raw 工具或本次返回指出的缓存文件获取新鲜版本信息。核对目标、时间和官方字段含义，不读鉴权文件，不固定私有缓存路径／嵌套结构，不把名为 `package_id` 的字段无条件当作版本 ID。源码里存在工具不表示当前会话已暴露。
3. 按当前官方能力核实二维码入口、环境／类型与版本参数；若拼接 URL，逐个核对参数语义。保存入口与本次版本／包哈希的关联，并反解二维码验证实际编码 URL。二维码、缓存、令牌及真实 ID 仅留项目证据，不写进共享 Skill。
4. 在已同意的设备上通过实际 TapTap UI 扫码；切包时退出旧游戏实例，必要时完整退出并重启 TapTap再扫。核对**实际加载 URL、运行版本／构建标记、入口原始字节哈希**与冻结包。标题、扫码成功、二维码中版本号或点击刷新均不证明已换包；不为排缓存清玩家进度。

官方 [MCP 工具定义](https://github.com/taptap/instant-games-open-mcp/blob/main/src/features/app/tools.ts)支持刷新参数；返回形状和二维码契约使用时重新发现。哈希比较区分原始 HTTP 字节与 CDP 序列化内容，样式表示差异不直接证明错包。

## CDP 是有条件的观测通道

动态检查当前 H5 进程及实际可访问的 DevTools socket；按实际 socket 建本轮端口转发、枚举目标，再用预期 URL／版本匹配唯一 H5 目标。不硬写 `chrome_devtools_remote`、固定 PID／端口或依赖标题选择目标。使用既有 Node 连接实际返回的 WebSocket，限制超时和采集字段，不默认注入游戏状态。

[WebView 官方调试说明](https://developer.chrome.com/docs/devtools/remote-debugging/webviews/)要求宿主开启 WebView 调试。发行 WebView 未开放时，CDP／Appium不能强行开启，也不能承诺执行 JS；改用授权范围内的 UI、截图、后台与现有游戏诊断取证，将无法核实的版本／哈希／用例标为待验。不能因观测缺失直接给 PASS。

## SDK 用例与结果分层

开始前逐项列明读写性质、真实测试账号／凭据／白名单、存档和奖励保护及预期回执。榜单只读打开、分数提交、云档写入、成就解锁、广告完播领奖分别执行、分别报告。未授权远端写保留待验；只读 SDK 用例不保证游戏正常启动的遥测或同步为零。

游戏 UI 打开原生榜并成功返回，仅证明这一用例。不能推广为广告、云档、成就、iOS、模拟器或完整体验通过。图片缺失按[部署资源排查](deployed-assets.md)处理；修复后的新包须重新绑定版本和证据。

在项目已有交付记录保存：目标／设备及工具版本、启动确认、包与入口身份、每项用例的读写性质及结果、必要截图／有界日志、实际后台状态和剩余问题。区分本地检查、真实宿主／设备、上传、审核、发布；一份设备回执不关闭其他验收层。
