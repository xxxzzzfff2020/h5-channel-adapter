# 引导式平台选择与信息补齐

通过对话选项与填写提示完成适配。用现有对话工具实现，不新增网页、桌面插件或审批系统。

## 使用当前实际支持的提问方式

若当前工具提供 `request_user_input_async`：每题可选一个建议项，也可直接填文本；一次可放几道相关短题。不把默认预选或等待超时当作用户回答，不声称它提供原生多选复选框。今后若实际工具支持多选再直接使用。

`request_user_input` 只在其当前工具说明允许的模式和用途下用，不能为显示弹窗擅自切换模式。无可用提问工具时，用简短编号选项和文本回复，不伪造弹窗。官方 App Server 文档记录了对话问答接口，但具体可用能力以当前工具 schema 为准：[官方说明](https://learn.chatgpt.com/docs/app-server#toolrequestuserinput)。

## 1. 开始时选平台

只有用户实际要求开始适配且未指定平台才提问；用户只讨论未来流程时更新约定即可。默认有两种案例支持平台，用一题表达全部组合：

```json
{
  "questions": [{
    "title": "这次要为当前 TapTap H5 项目准备哪些平台？选择后我会先生成独立源码和全套上架物料。",
    "options": ["233＋4399（推荐）", "仅 233", "仅 4399"]
  }]
}
```

这只是参数示例，通过实际提问工具调用才会出现交互卡片。自由文本可指定其他组合，不另加“其他”伪选项。已有明确选择、用户说全部已支持平台、用户直接说某平台则省略此题。

平台超过少数组合时，按平台给出“本次适配 / 本次不做”的短题，每组建议 2–3 题；用户也可一次文字列出目标。星匣/小红书/B 站 TOY 注明“文档已核对，待首个项目验证”，不与已成熟渠道一起承诺直接交正式包。

必需的平台选择尚未回答时，继续检查源码/资源，不开始未选定渠道的目录创建和改写。若用户只说开始且当前上下文有多个可能源项目，先通过已知项目名选项确认源；不能从工作室总目录猜游戏。除此之外，不再让用户选择普通工程实现细节。

## 2. 第一轮自动完成

按选定平台建立工程、复制完整源与运行资源、适配代码/兼容、本地验证，生成全部初始物料和文案。尽可能自行补录；确有缺资源时聚合问题，仍继续独立工作。

缺资源优先问现有资源位置或可行偏好，例如“未找到实录，可从本地版本录制 / 我提供现有录像路径”。本工具仅收文本，不用它请求附件上传；确需图片/录像附件时在普通答复说明所缺内容。

第一轮结束按实际证据展示表格，不用笼统“都已完成”：

| 平台 | 源码/物料 | 游戏 ZIP | 你接下来需要做什么 |
| --- | --- | --- | --- |
| 无凭证阻塞的平台 | 各项状态与目录 | 已生成：候选包链接 | 需要后台应用时先建项/绑定后上传 |
| 必需身份字段缺失的平台 | 已准备；列真实缺口 | 本地预览；正式包待配置 | 用建项资料创建应用并补字段 |
| 权限尚未批准的平台 | 各项状态 | 若允许，可交功能降级候选包 | 等权限开通，再验证相应功能 |

表中是展示方式，不预先承诺233必然完成或4399必然阻塞。每个平台都可能缺素材或检查失败，应准确列出。可上传 ZIP 只代表本地候选产物，不等于平台上线、审核或真实 SDK 已通过。

## 3. 引导建项及状态填写

先提供平台准确建项入口（使用时核实官方 URL）、可复制名称/介绍/操作说明、图标等链接，说明这一平台需要建立哪种应用。用户自行建项时不替他登录日常浏览器。

只向需要的渠道提问。例如 4399 缺 AppID：

```json
{
  "questions": [
    {"title": "4399 应用建立后，请填写本游戏 AppID（只填数字即可）。"},
    {"title": "4399 激励广告目前是什么状态？", "options": ["已开通", "申请中／待审核", "未申请或暂不开通"]},
    {"title": "4399 存档 API 目前是什么状态？", "options": ["已开通", "未开通", "不确定"]}
  ]
}
```

状态题不暗示推荐用户谎报已开通；选项顺序按已知情况调整，预选不是答复。排行榜只有原游戏需要或用户明确要求才收集开通状态、榜单 ID、分数含义/范围/排序。不存在这项功能时不强迫开通。233 当前 IAA 前端不需要 AppID 参数，不为它复制一套无用凭证问卷。

用户可自由粘贴“4399 AppID xxx，广告申请中，存档已开，暂不做排行”，直接解析并续做；不要让他再逐题填一遍。只有身份冲突/缺失才针对性追问。星匣运行时 gameId 由宿主注入，不要求前端 AppID；登录和作品绑定只在预览/发布阶段按需引导。小红书初轮需要当前上传页的改写命令，不能以 AppID 代替。Secret 类信息按 SKILL.md 的服务端安全配置规则处理，不设计明文密钥收集表。

## 4. 按平台继续交付

收到足够信息，更新本游戏渠道配置，运行相关检查出包。缺 ID 的渠道等 ID；其他渠道继续。权限申请中但可安全关闭该功能时仍可出候选包，明确能力状态；不能将“已填 AppID”自动推断为广告、存档、排行全部获批。

在已有 `docs/待补充信息.md`/`docs/渠道交付.md` 记录：选中渠道、已知非敏感字段、权限状态、游戏/物料 ZIP 入口、缺口和下一动作，不另建重复进度系统。用户下次补数据直接恢复未完成部分，不重拷源、不覆盖旧档、不重画所有物料。

最后按平台给出完整工程、游戏包、物料包及说明；需要时再问上传后测试地址。初轮确认的是平台范围，后续填写的是缺失配置，普通本地步骤无需再次批准。

## 超限时的方案选择

选中渠道超限即按[包体流程](package-budget.md)展示实际大小/限额/超出量与主要资源，只给可行选项：保留功能优化、去背景音乐保留音效、去可选游戏内视频、明确组合或暂缓。收到具体选择后再删减；已有同范围明确选择直接沿用，不能把默认/超时当答复。需要选择是因为删功能改变交付内容，不是普通本地打包要审批。
