# H5 可靠性合同与验收配方

这是可复用工程建议，**不是平台规范或已交付公共模块**。先检查目标源码、存档／经济规则和当前官方接口，再只采用已选范围。已有稳定架构不为统一而重写；项目 ID、槽名、数值、超时及历史通过数量不进入公共规则。

## 身份、本地存档与云

- 身份未知时可在隔离本机作用域继续游戏，冻结账号云档、排行榜和成就写入。网络恢复不是身份确认；账号、云 UUID、本地 key、存档谱系、请求 generation 分开。
- 所有存储访问容错，包括取得 `localStorage` 对象、读取启动偏好和写入。内存游玩、本机持久化、云同步分别显示。候选校验后提交；迁移／导入／云覆盖前保留可校验备份。checksum 是检错，不是反作弊；旧客户端不能覆盖未来 schema。
- 原生方法存在只代表能力线索。依赖前核验真实同步／回调合同及完整写入／读回；把异步文件写入排队不能满足同步存档事务。结果不明时保留原快照和身份，不静默新建档，也不把仅内存游玩报成持久化。先确认权威存储和既有恢复策略，再按有界的[可选原生备份启动策略](native-storage-boot.md#可选原生备份与浏览器启动)处理。
- 读取分为明确不存在、存在且有效、存在但损坏、结果未知。只有对应操作／路径的明确官方缺失结果才能证明不存在；通用 `errMsg` 文本或本地标注的“missing”类别不能证明。浏览器兜底须校验归属／谱系，并保留任何已知原生档。
- 奖励与完成回执同一事务提交。保存失败回滚，或保留不可重复消费的“奖励已确认、待保存”恢复状态；内存变化不能报持久化成功。权威槽已提交时，兼容镜像失败不推翻它。
- 云启动单飞；超时、重置、切号后的回调用 generation／settled-once 隔离。读取失败不是空云；A 切 B 空云不能把 A 本地档写给 B。保留已有手动／自动同步产品决策。
- 同谱系且先后关系可证才自动对账，覆盖前备份。语义等价比较仅决定是否需要冲突选择器，只忽略已证明不影响内容的展示时间戳、等价默认值迁移或设备偏好。分数／进度／收集总数相等不代表同档：须比较实际完成 ID、奖励／广告回执、连续签到、事件时间、当前状态及归属／谱系。具体差异类别或数值放在长对比卡片之前。防过期选择／写入保护仍用独立严格快照及原远端 token，不能用语义相等授权覆盖。余额较大、时间戳较新、不同设备 revision 不能单独判胜，不跨谱系相加或 max 资源。
- 上传成功回调不等于远端内容已核验。使用平台返回的存档 ID，再重新列档／下载，核对本次操作回执、归属和载荷后才显示“已保存并核验”。创建回执缺失或结果未知时先重读对账，不重复创建，也不因连点／重启重复结算。
- “云端已有另一设备更新”等提示可能只是同步基线冲突，不能只凭文案断言存在第二设备或丢档。后续等级／进度增长证明有新进度，但缺少退出前后成对快照与回执时，不能宣称原问题永久解决。
- UI 取消／Promise 超时只使本地结果失效，已发远端写可能成功。每次提交前，将 pending 操作证明与节奏状态分开持久化并精确读回，保留原账号／操作／存档绑定、预期远端 token／版本及稳定快照证据。未知结果跨刷新保留，不重叠重试，清除或重试前核对身份与完整内容／checksum／读回；计时或迟到回执本身不能证明远端内容已核验。保留备份、游戏 key 与奖励防重复保护。客户端预检、lease、读 revision 再写都不是服务端 CAS 或原子锁。
- 主档与诊断共用配额时统一仲裁、主档优先，诊断可丢弃；合并最新待写状态，真正提交前序列化。按当前官方配额和错误类型设置有界重试／退避。主档读取不得依赖可选诊断／配额文件。诊断写入方已关闭时，选定的主保存设计也可移除提交对退役辅助文件的依赖，采用仅会话内尝试节奏；这不保证服务端配额或跨会话／标签页／设备仲裁。关闭诊断不删除旧未知操作标记，也不放宽主档账号／token／读回保护；先区分标记归属，再采用启用协议的恢复策略。TapTap 读取兼容、可选旧协议恢复与受保护提交见[平台专项说明](taptap.md#云档读取兼容与上传预算)。

**验收：**getter/read/write 抛错、存在但不可用的原生方法、同步边界遇回调式写入、明确缺失与仅 errMsg／未知读取、配额耗尽、读回不一致、主／备档损坏、未来 schema、旧档迁移、多窗口轮流写、奖励写失败与刷新恢复。云另测双真实账号／会话／设备、空云／旧云／分叉、总数相同但内容不同、仅展示字段变化后的过期选择、请求中切号、创建回执缺失、超时后实际写成功、可选文件失败但主档可读、诊断竞争。替身测试不能关闭真实账号门，破坏性测试使用隔离测试档。

### 云保存队列与真实状态

在已有同步产品策略内采用以下要求；它们不是已实现的队列，也不证明某个来源设计普遍优于其他方案。保留上文身份、冲突、严格快照、奖励与未知写入保护。

- **最新意图与本次请求分开：**重复保存合并为按账号／谱系隔离的待写意图及 generation。通过执行资格检查后，在实际发起时生成当前 JSON；本次请求的快照／generation 单独固定。请求期间的新保存继续待写，旧请求完成不能将它标为已同步。本地提交证据、当前内存与云端代次分开记录；保留 provider 或 RAM 写成功不证明本机持久化。
- **等待有界，硬门不绕过：**从首次待写意图计算合并的最长等待，避免每次操作重置截止点而饿死。到达上界仅取得调度资格；已核实的平台配额、退避、身份与对账仍可继续延期。手动／关键保存只改变顺序或合并紧迫度，绝不绕过硬限频。首次创建、替换、重试和独立控制器均遵守适用的同一预算；客户端仲裁不能消除跨设备竞争。
- **失败不能吃掉意图：**从 pending 转入 in-flight 不代表结算。明确失败时保留／重建最新合法意图，即使没有新保存也要安排有界恢复；已有更新意图时保留它，不用旧 JSON 覆盖。pending 已清空时，仅设置退避时间戳和执行 `finally` 不够。还须处理 provider／序列化失败及 busy／限频提前返回。重试耗尽仍保留真实的待处理／错误状态及安全操作。远端结果未知时先重读对账再提交，退避时间经过不证明写入失败。
- **暂停任务，保留进度：**后台／切号取消须保留权威本地进度，或明确标识的易失状态，以及未同步意图。重新排队前验证身份，执行时及异步阶段后核对账号／谱系／运行时代次，使旧 provider／回调失效。仅内存／仅云端路径、普通自动保存、手动保存与 teardown 同样受这些门约束。取消计时器不能取消已发远端写，结果未知仍须保留；不能依赖退出回调完成，也不能承诺 RAM 退出后仍在。
- **安静且可恢复地等待：**排队／延期是正常、不阻塞游玩的状态，不逐次保存弹 toast，不无限转圈。保留最近成功云操作时间，并区分其含义是上传、读回还是下载校验；按原因提供安全的重试／对账／冲突处理入口。不承诺准确完成倒计时。排队文案与恢复动作须对应实际保留的工作；本机写失败应更新状态，不能一直用“自动保存已开启”作保证。

本地化文案从证据推导，不从 `synced` 等枚举名推导：

| 证据／状态 | 真实展示与恢复 |
| --- | --- |
| 当前代次已持久化到本机 | “已保存到本机”；云状态独立展示。较早的本机提交不覆盖更新的内存变化。 |
| 本机写入失败 | “未能保存到本机”；保留可恢复状态，区分已回滚与尚未保存的内存，提供已有的保存恢复入口，不报本机成功。 |
| 仅内存／本机存储不可用的仅云端模式 | “临时进度”／“本机存储不可用”；说明云端已确认到哪个代次，或尚未确认。确认前说明退出风险；有云能力或 RAM 保存不等于云提交。 |
| 不支持／无排队任务的空闲 | “当前环境无法使用云存档”／“尚未同步”；不永久显示排队，也不提供不可能生效的重试。 |
| 排队或延期 | “云备份排队中”，必要时说明原因；只有对应代次有持久化证据才能加“本地已保存”。 |
| 核对／下载中 | 说明正在读取／核对，不表示正在上传或进度已保存。 |
| 已下载并校验 | “远端存档已核对”；它是仍受归属／谱系、完整存档校验与冲突保护约束的恢复候选，不是最新本机进度已上传。 |
| 上传中／收到成功回执 | 对固定代次显示“正在上传”／“已收到上传成功回执”；回调不等于读回核验，新待写进度仍须可见。 |
| 读回已核验／一致 | 指明核对的代次／内容；匹配归属、回执和载荷并通过校验后才能确认已核验同步，仅元组／摘要相等不够。 |
| 错误／结果未知 | 保留最近成功时间、当前持久化情况和待处理原因；明确失败按预算重试，未知结果先对账。 |

后续实现使用[队列／状态验收矩阵](../../assets/validation-status.example.md#cloud-queue-and-status-acceptance--云队列与状态验收)。源码字符串断言、延迟算式及替身构建检查不证明端到端重试、当前代次文案或真实宿主／真机验收。

## 离线、签到与广告

三者分别属于产品合同，不因平台有云或广告就全部添加。

- 冷启动与同会话回前台共用离线结算；时间高水位保证区间只推进一次，覆盖回拨、连续回归、午夜和上限。保留原经济 gate 与超限丢弃规则。
- 有待领收益时分时间、资金、广告三本账：旧未领不能冻结工程／时间或丢新钱。直接入账项目不强加 carried-money。广告隐藏时间不重复算离线，返回重置帧钟。
- 签到先定时区、连续／累计、首日资格与结束条件；奖励、标记、次数一起落盘。同谱系回旧档保留防重复水位，不按 max 或相加合并余额。日界线／活动版本变更要迁移；日常任务与广告配额独立。本机时钟防回拨不是可信服务器时间。
- 广告生命周期：资格 → 固定目标、奖励和唯一请求 ID → 绑定监听并确保素材就绪 → 发起显示 → 校验原账号／请求／目标的官方完成 → 执行[确认与入账合同](#奖励确认与可恢复入账) → 提示已保存。显示前保存的请求 pending 不是完成凭据。奖励请求与显示／恢复尝试分开；完成事件不必等待展示 Promise resolve。可重置日计数不能作唯一 ID，时长、失焦和计时器不是完播证据，单机去重不承诺跨设备 exactly-once。实例所有权、外跳、未知结果、有界恢复／诊断与宿主验收见 [TapTap 专项配方](taptap.md#激励广告生命周期与漏奖励排查)，其回调结构不套用其他平台。

**验收：**旧回执加新离线区间、分段与整段结算、同日多次广告、pending 目标变化、重复／迟到／取消／不回调、pending 与奖励写失败、刷新与声音恢复；日界线迁移、回旧档、回拨与跨账号隔离。

### 权益时钟、日界与旧档迁移

**2026-10-10 热修复经验：**已检查源码差异、单元及隔离浏览器回执，另有 Owner 两个真实账号扫码后行为正常的反馈。以下复用已选的兼容修复，不扩大时间回拨防作弊范围，不强加服务端时间或新系统；具体额度、有效时长与时区沿用目标产品合同。

- **采样基线：**offset 型时钟若保留旧 `lastReal`，每次读取又累加 `lastReal - realNow`，会重复补偿同一次回拨并把权益时间推向远未来。推进相邻采样基线，测试回拨后高频重复读取与恢复；模拟 delta／测试偏移不驱动权益墙钟。只能将确认触发条件下的权益时间污染认定为缺陷，不能推断所有存档均坏。日界不能永久 `max` 已污染的历史未来时间。
- **主档与确认日志一起迁移：**先加载两者，校正各自日界及时间高水位，避免 journal 把修过的主档重新推到未来。对于已选修复且产品以当前日期为准，按配置时区比较：日期不同重置相应每日额度，同日保留已用次数。仅在同日、同谱系且合同允许时对账次数；保留完成／确认序号、已入账 token 和待入账权益，不能为了清理日期清空日志。主档／journal 写失败、重启及重复回调继续按[恢复合同](#奖励确认与可恢复入账)保证同权益不重复入账。
- **加速与 pending：**合法权益按真实设备墙钟倒计时，不因旧未来高水位永久冻结。到期时间超过产品允许的最大剩余时长时，按已确认迁移规则恢复或过期；不照搬案例时长，也不扣已入账资金或补出新免费次数。未来创建或过期的**未确认 offer**须失效；已确认待保存权益不因此丢弃。
- **时间领域分开：**权益时钟、离线结算锚点与云排序元数据不同。修正未来 `lastTick` 不制造虚构离线资金，已有 `pendingOffline` 收益回执保留。`updatedAt`／`revision` 按既有云排序合同处理，不能一并回拨导致修复档被判旧；也不从元数据未来高水位推导广告日期／加速时间。不能跨谱系机械 max 时间戳或 revision。
- **实际跨日刷新：**明确产品日界，例如已验证案例采用北京时间零点。开局、保存、请求广告时校验，长开页面也要在实际日界更新额度／按钮，无需刷新。资金与经营加速额度分开；离线扩容属于该收益回执，免费加速不等于看过广告。每个按钮按当前回执的 eligibility 判断；已结清或尚未达到扩容条件不能套统一可用假设。

**迁移验收：**用获准的真实匿名档只读导入隔离环境，逐项比对资金、等级、工程／迭代、永久倍率和未领离线回执；不上传原档或输出存档正文。覆盖启动、重启、数日后、准确日界前后、合法倒计时、同日已用次数保留、主存储／journal 故障及失败后单次恢复。测试执行真实时钟、迁移、账本与存档逻辑；SDK-ready mock 仅为隔离浏览器条件，不证明真广告发奖或云写。

**证据分层：**Owner 真实宿主扫码反馈单独记录账号数量和反馈内容，账号标识留在受保护项目证据中。缺少设备型号或逐广告轨迹时，不扩写成完整 Android／iOS 矩阵通过。来源测试数量、构建及上线状态留本地回执，不成为本 Skill 的默认成绩；最新审核包须按[版本级状态](taptap.md#构建身份路径与版本级发布状态)另验。

### 奖励确认与可恢复入账

仅用于已选择的激励广告工作，沿用游戏已有存档与产品合同。Banner／插屏可以复用生命周期原则，但不因此产生奖励权益。以下是待实现、待验证的工程约束，不表示 Skill 已提供通过测试的运行时适配器。

- **两层去重：**`requestId` 防同次回调双发；另以账号／档案谱系＋局次或结算实体＋**具体权益实例**构成领取键。同一权益换请求不能多领；通用 placement／offer 类型名不能单独作领取键，避免挡住合法的下一笔奖励。将奖励内容与该身份一起冻结；同权益再次看广告前，先处理已确认未保存记录。
- **先确认，再持久入账：**目标需要跨刷新恢复时，核验官方完成后先持久化冻结的确认记录。再将奖励与 `creditedToken` 作为同一主档事务／快照提交，成功后才清确认账本。请求 pending、平台已确认、已持久入账是三个状态。本地 token／hash 仅作关联或完整性校验，不是平台验签收据或服务端验证。
- **重试不重复加资源：**游戏保存失败时保留已确认权益、明确且不可提前消费的待保存状态；从可信快照或已明确回滚的状态重试，不向已改过的内存再次累加，也不要求重新看广告。主档成功而账本清理失败时，重启读到已入账 token 后只清残留账本。确认账本也不可写时，只能保留内存并提示关页会丢恢复能力，不能承诺重启后补发。
- **按原上下文恢复：**恢复时先加载主档与确认账本。同谱系旧云／本机档覆盖须保留或对账已入账水位，否则残留账本可能重发已消费奖励；不跨账号合并，也不按 max／相加合并资源。谱系不明先对账，不盲目重放。背包满、换局或离开原页面不能静默丢掉已确认权益，也不能发给当前新局；按明确的既有产品合同保留／路由，不为套用案例擅自增设邮件或服务端系统。

**实现验收：**执行真实适配器、计时、账本和存档层，只替换 SDK、可控时钟与故障存储。覆盖同权益新请求、合法新权益、确认账本写失败、奖励／token 提交失败及同页重试、主档成功而账本清理失败、真正重启、旧云／本机档覆盖与领取水位、切账号／局次、背包满；平台层另验完成早到和确认后拒绝。场景清单或仅验证假 SDK 本身不算执行证据；真实宿主生命周期／完成事件与跨设备保证分别验收。

## 排行榜

固定榜单 ID、整数指标／范围、编码版本、方向、同分、覆盖／合并与资格。超大财富不强转不安全 JS Number，不暗加小数排序。测试／调试／特殊导入档明确资格；未知身份禁提交。

状态按账号、saveId 和榜命名空间隔离；换榜必须能首投。成功回调只确认本次快照，不能清掉提交中新增的待交值。历史最佳榜和当前状态榜不能一律 max。切号、换档、换榜使旧 generation 失效，排队／同步／成功／失败／超范围／不支持状态如实表达。

**验收：**边界／非法值、同分／升降分、新榜首投、提交中变分、永久无回调、旧回调、恢复重试、真实读回、昵称／头像／本人行。打开榜单不等于成绩上榜，客户端成绩不等于服务端权威或反作弊。

## 音乐、音效与设置

- 统一控制器管理用户意愿、场景、后台／广告和实际后端。长 BGM 可复用原生媒体元素，短 SFX 可用 WebAudio；已有稳定后端先测量，不机械替换。编码码率不等于解码 PCM 内存。
- 首次手势直接发起 play；旧播放 Promise／资源事件隔离，自动播放拒绝等待新手势。意外停滞有界恢复，不无限新建上下文或重载；加载 `suspend` 不是暂停证据。音量 0／muted、设置暂停、广告临时降音分别管理。
- 固定合成循环可把**本项目自有旋律**预渲染，解除对 rAF 补排的依赖；保留尾音并试听接缝。动态作曲、逐音交互、严格音游同步另设计；不强制某种格式、秒数、采样率。
- 循环时钟回零是进展。主线程阻塞测试应在后续事件循环任务读媒体时钟，处理回零并观察新合成节点；时间推进／running 不等于扬声器无断音。诊断不能主动解锁音频改变故障现场。
- 音乐／音效开关音量独立，偏好保存失败有反馈；云恢复时偏好随档还是随设备要明确。手势、焦点、广告返回尊重静音／暂停。字号覆盖按钮、弹窗、Canvas、长文案和最大字号窄屏；字体加载失败用可读 fallback，字号支持不能证明任意字体家族切换。
- 省电／减少动效只改变表现，不改变经济或模拟。振动不可用安全降级；重置设置、重开、删本机档、删云档分别表达。

**验收：**冷启动、首次手势、切场景／曲目、完整循环与接缝、静音／0 音量、暂停／恢复／刷新、保存失败、play 拒绝／停滞、旧 Promise、加载失败、广告成功／取消、后台／锁屏／来电、最大字号窄屏。真实 iOS／Android 宿主试听及长时运行独立记录；一个历史手机试听不能认证另一个项目。

## 开发者与 Owner 工具

仅在开发者／Owner 控件属于本轮范围时应用；这是共享指导，不代表某游戏已完成实现。解锁内容、加资源、改速度、跳层／跳关、即时测试广告奖励与诊断面板统一收纳到**设置 → 开发者／Owner 工具**。不在普通游玩页面常驻作弊按钮、横幅、悬浮入口或遮罩，尤其不能挡住安全区／胶囊附近控件。复用既有设置流程，入口保持可达，不另加遮挡。

- **构建与存档边界：**调试版可保留工具与隔离测试档。生产版不得暴露作弊或模拟广告完成入口，包含可被 URL／存储开关或快捷键调起的隐藏处理器；仅藏按钮不够。没有作弊系统的游戏不因此新增一套。保护自然存档，改过的测试状态不得进入普通云档／榜单流程。若明确选择了生产版的非作弊支持诊断，仍放在设置中，遵守有界脱敏诊断合同。
- **奖励边界：**明确标注测试奖励与模拟状态。测试发奖与真实 SDK 完成分开，不计作真实看完广告、不消耗真实资格、不改变权益幂等和结算规则。保留既有[奖励合同](#奖励确认与可恢复入账)，包括待保存恢复；调试捷径不是平台奖励证据。
- **暂停与偏好：**开关工具须与手动暂停、广告、后台生命周期共同生效，不能强制恢复游玩／音频。保留既有静音、音量、速度及其他偏好，除非 Owner 明确改动。关闭后清理弹窗点击拦截、残留遮罩和监听，恢复合适焦点及原暂停状态。

**验收配方：**在实际量测的窄屏手机视口，检查工具关闭后的稳定游玩画面：无调试条／遮罩、按钮遮挡、点击拦截及安全区／胶囊冲突。从设置进入工具，执行已授权的隔离测试，关闭后继续正常游玩。覆盖长文案／最大文字、反复开关、手动暂停、切后台／返回、广告、原有静音及偏好不变。核对实际生产制品没有作弊／模拟入口，并单独检查调试档隔离；开发截图或源码开关不能证明生产排除。按[验证记录](../../assets/validation-status.example.md)填写构建／版本、实际视口、设置路径与证据；技能指令更新、项目实现及实际浏览器／宿主／真机结果分别报告。

## 启动、布局、性能与诊断

独立最小 HTML 错误页覆盖模块下载／解析、同步／异步初始化和超时，显示构建／错误码，重试仅 reload 不删档。可操作 UI 或云预检建立后撤守卫。构建 target 不会补齐全部 DOM／Intl／存储 API。同源 HTTP 预览才适合验证构建；file:// 开发源码打不开不是玩家故障根因。

Viewport、DPR、渲染缩放、安全区和输入逆变换共用合同，避免重复乘 DPR 或把 Maker NanoVG API 贴入 DOM／Canvas。一次事件用一致快照；宿主原点与刘海／胶囊按[安全区合同](#安全区宿主原点与胶囊布局)处理。测窄屏／长屏／平板、安全区、最大文字、旋转与实际点击区域。合成输入去重与权益幂等分开，核对运行时事件而非任意 debounce。

用新档、中期、高进度档测量；区分 JS／布局／绘制／输入与产品节奏。先减少重复模型、DOM 读写和强制布局；展示可缓存，交易仍用最新状态校验。表现限频／滚动让路不得暂停模拟、保存或丢结构同步。**同一页面实例**跑首次解锁、转阶段、重生、入口重现和后期，逐阶段刷新会掩盖 hidden 状态残留。不要统一规定帧率，或据 FPS 截图断言设备唯一根因。

独立诊断云档默认关闭；保留有界本地收集／复制及明确获准的宿主／MCP 反馈，关闭云诊断不关闭无关 HTTP 分析。停用入口在序列化载荷及访问 SDK／文件系统之前返回，循环引用／超大输入同样如此；启动时不构造／订阅诊断控制器，也不排入会列档／读写文件／创建／更新诊断云档的任务。旧诊断云档和未知操作标记保留。停用消除的是该流量，不能证明所有云错误或跨设备风险已解决。

明确重新启用时，诊断仍是可选旁路：独立 schema／槽，不参与游戏恢复，UUID 由平台分配。使用字段白名单、有界字符串／计数及完整包装后的 UTF-8 字节门。保留构建／阶段、可用宿主／设备字段、数字码、回调字段类型和固定错误类别；包装器须保留失败位于读取还是配额／写入阶段，以及数字码是否缺失。不记录原始 SDK 对象、本地路径、UID、存档正文、token、签名 URL、任意异常 payload 或无限日志。缺字段省略；遵守前述共享预算，失败不阻断游玩。游戏中明确用途／访问／保留规则，不承诺每次启动上传诊断或模块启动前／系统杀页后的故障必有记录。

**验收：**缺 API／模块／资源、入口前存储异常、同步／异步错误、不删档恢复；实际布局输入与同实例结构生命周期；中文／emoji 体积、序列化／文件写错、不回调、共享配额、切号、首次创建竞争、诊断停用时 SDK／文件系统零调用（含循环引用／超大输入）、旧 pending 保留和诊断失败旁路。

### 安全区、宿主原点与胶囊布局

仅用于本次选中的布局工作；这是指导，不是随 Skill 提供的运行时适配库。区分屏幕坐标下的原生安全区、原生窗口／WebView 矩形、CSS 布局视口、`visualViewport` 与宿主胶囊遮挡。合并前核对有限数值、矩形顺序、单位、方向及同一份几何快照；按对应窗口尺寸换算到 CSS 坐标，不再乘一次 DPR。键盘／缩放导致的 `visualViewport` 变化不自动代表原生窗口变化。

同一原生坐标系下，合法竖屏几何只换算**窗口内尚未避让的遮挡**：

```text
nativeTop    = max(0, safeArea.top - screenTop) * scaleY
nativeBottom = max(0, screenTop + windowHeight - safeArea.bottom) * scaleY
```

若 CSS `env(safe-area-inset-*)` 仍描述同一屏幕安全区，只减去原生窗口已消耗且可证明的部分，再取 `max(nativeRemaining, cssRemaining)`。不把两路直接相加，不重复扣减，不把竖屏坐标套到横屏。只有窗口原点、没有 `safeArea` 时，也要用已知原点扣减适用兜底。未知原点／几何保留未知，不当成测得的零。左右边距与内嵌窗口须另核对文档中的原点与变换。

- **兜底范围：**优先有效原生／CSS 测量。缺失、抛错或零值既不能证明没有遮挡，也不授权给所有宿主加刘海留白。须明确识别设备／平台、当前原生宿主与方向，才可针对已证实缺口配置有界兜底。UA 受限或型号未知不算已识别；保留已正常的 Android、传统 iPhone、平板、横屏和浏览器路径。仅顶部有依据时不顺带猜底部留白。
- **胶囊布局：**用局部标题栏／操作区避开真实右上角遮挡，不为保护该角额外增加全局纵向工具栏、缩小所有页面与滚动区。应用矩形只为实际系统／宿主边距让位；在局部胶囊区域检查长标题、弹窗与关闭按钮。
- **生命周期：**兼容 API 缺失、抛错和不可用数据。基础设备身份按宿主绑定缓存，换宿主时失效；可选异步结果须校验视口／宿主代次和 dispose。按实际窗口、方向及前台变化刷新，不阻断游玩、不积累监听。诊断有界且仅含几何，不含原始 UA、玩家身份、凭证或业务遥测。

**有界案例，2026-10-16 核读：**全局竖屏留白先造成空白过多；移除后 Android 间距获 Owner 认可，但 iPhone 顶部出现遮挡。后续候选只对已识别的竖屏 iPhone／iOS 原生宿主、且**屏幕长短边比 ≥2** 时使用 **64 CSS px** 顶部兜底，并在局部标题栏预留 **100 CSS px** 胶囊区域。这些是该项目的启发式与布局选择，**不是 TapTap 官方尺寸或通用默认值**。反馈没有原生几何，测量缺失／错误仍只是推测。后续 iPhone 修复只有依赖替身覆盖，尚无原生 iPhone 验收；桌面横屏冒烟不能验证竖屏兜底。

**回归配方——须在目标的真实布局／运行时代码上执行：**

| 情况 | 可观察结果／证据 |
| --- | --- |
| 无刘海 Android、传统 iPhone、iPad、桌面与横屏 | 保留已正常间距，不误加其他手机的兜底。 |
| 有测量的 iPhone；CSS 与原生边距同时存在 | 只避让一次，关键控件与滚动边界可用。 |
| 几何缺失／抛错／零值；UA 受限或原生身份未知 | 仅明确符合条件时兜底，否则记录该情况未验证。 |
| 全部／部分已避让窗口，包括有原点但缺 `safeArea` | 不重复预留已消耗的顶／底边距；局部原点扣减适用兜底。 |
| 身份／几何晚到、换宿主、resize／前台与 dispose | 旧回调不能恢复旧留白；监听得到清理。 |

页面稳定后记录**实际** `innerWidth/innerHeight`、相关 `visualViewport` 宽高／偏移及应用／标题栏／控件矩形。场景名、对未激活标签页提出的尺寸请求不是视口证据，过渡帧不算视觉通过。原生截图可能不含物理黑色刘海，须结合几何与 Owner 观察。尊重被拒绝的浏览器／真机动作，不换路重试。单元替身、浏览器布局、原生 SDK、真机及 Owner 验收分开；反馈“已处理”只代表分拣，公开测试不等于正式发布，上传制品仍需独立核对版本／哈希。使用[验证记录](../../assets/validation-status.example.md)。

## H5 上传与发布授权

按当前 Owner 指令与工具实际副作用执行，不套用统一再确认门槛。依 **2026-10-16** 更新的 Owner 规则，已授权任务内使用 `taptap-cli` **仅上传** ZIP／构建目录，无需每包二次确认；首次上传、开发测试、热修复和重传均适用。本条不授权范围外的新上传。其他渠道／工具按实际任务授权和适用工具要求执行，不擅自套用 CLI 豁免，也不另设通用审批门槛。

上传前完成必要本地检查，记录目标平台／`app_id`、精确路径、版本／SHA-256（目录用构建清单及哈希）、用途及命令实际副作用。对已授权的 CLI 纯上传，这些是执行核对和交付证据，**不是额外确认步骤**。上传后回读包／版本状态；结果未知先只读核查，不自动重复上传。

CLI 上传豁免不覆盖主包绑定、提审、发布、撤回、下架、回滚或平台配置变更，均按各自具体授权执行；组合 CLI 命令不是纯上传，不能扩大豁免。Owner 要求上传但不走发布流程时，停在上传完成与状态回读。不得换用浏览器、脚本、API 或放宽设置绕过发布所需确认。TapTap 已观察到的 MCP 上传／提审耦合按[自动提审影响边界](taptap.md#自动提审与发布影响)执行；计划后续撤审不授权之前的提审。
