# 游戏包体检查与超限方案选择

检查两次：接入时的冻结 TapTap 原始包，以及构建后的各渠道实际上传包。限额唯一机器表为 Skill 根下 `assets/package-rules.json`。当前快照：小红书 ZIP 10 MB、B 站 ZIP/HTML 140 MB、星匣已有游戏轨道 A 50 MB（来自此前官方文档；这次“工坊管理”示例未给新上限）。233/4399 包体上限仍未知，绝不能把宣传视频配额当游戏包配额。MB 按十进制保守计算，使用时复核真实表单。

## 先测量，再提问

优先现有权威 TapTap ZIP；没有则沿用原构建，在隔离位置生成基线。不能拿整个源码目录或物料 ZIP 大小替代上传包。记录版本、哈希和真实文件字节。渠道打包可能变大或变小，初始包通过仍需检查最终包。

```sh
python3 <skill-dir>/scripts/check_package_budget.py <TapTap游戏.zip> --channels xiaohongshu bilibili-toy xingxia --report <新的包体报告.json>
python3 <skill-dir>/scripts/check_package_budget.py <渠道游戏.zip> --channels xiaohongshu --stage candidate --report <新的最终包报告.json>
```

Windows 换成已核实的 py -3 或 python，真实路径加引号。工具只读，不依赖 ffmpeg、不删资源；输出真实包大小、限额/未知项、超出量、按 ZIP 压缩后/解压前统计的资源占用、最大文件，以及有限范围内的内嵌音视频标记。扩展名不能证明是 BGM 还是音效、视频是否必需；base64/内嵌媒体可能记在代码里，提出删减前须读源与构建。此工具不等于完整 CRC、运行或上架验收。

退出码：0 已在已知限额内；1 超限需要选择；2 输入/候选格式错误；3 限额未知仍待核实。1/3 不是瞬态故障，不循环重试，也不把未知当无限大。

## 超限时必须引导用户选择

发现选中平台超限就提示，并在实施删减前询问方案，不等到 AppID 阶段。等待时继续其他平台和独立物料。已有明确且仍适用的该渠道选择直接沿用；不能把超时、默认预选或另一渠道的决定当成答复。

展示当前大小、上限、超出量、主要资源，以及有依据的预计节省量与玩法影响。可在临时隔离产物中试算，不改权威源；预计能省不等于最终合格。只展示实际存在的方案，例如：

- 保留功能，排除确定未使用/重复的运行文件，并在同意的画质/音质范围内优化编码压缩；已压缩的音视频再次压 ZIP 未必有效。
- 移除背景音乐、保留音效，明确区别于移除全部声音。
- 移除可选的游戏内视频；关键剧情/教学视频先提供认可的替代方案。
- 组合明确的删减，或暂不发布该平台、其他平台保留完整版。

选中方案执行后仍超限，报告新的实测结果并再次选择后续删减，不能自动扩大删减范围。小红书离线容器不能转外链/CDN绕过限额；其他平台外链也要先核平台支持与用户范围。

## 删减必须完整落地

只修改该渠道独立工程，记录选择、影响功能/资源、前后哈希/大小，保留 TapTap 原源与旧包。

移除音乐/视频时，同步处理资源、引用、manifest、预加载/进度总量、解码/播放器、所有播放点、生命周期/广告返回恢复、场景脚本、设置开关/滑块、菜单、帮助文案与降级分支。不能只删文件或只藏开关。仅移除 BGM 时保留音效；涉及玩法/剧情/教学依赖必须有已确认替代，不能静默删掉。

旧存档继续可读，可兼容忽略旧媒体偏好，但不清进度或改无关字段。测试新/旧档、启动、切页、设置、相关场景、前后台和适用广告返回；确保无资源 404、死按钮、无限等待、错误宣传或残留打包媒体。重建后再次测最终 ZIP。
